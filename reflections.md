Git Branching, Merge Conflict, and Pull Request Reflection

1. What steps did you take to create and manage branches?
  - started from the main branch.
  - created a feature branch and made my changes there.
  - committed and pushed my changes to GitHub.
  - This kept my work separate from the main branch.

2. How did you handle the merge conflict?
 - checked the conflicted file and reviewed both changes.
 - kept the correct changes and removed the conflict markers.
 - saved, tested, staged, and committed the resolved file.

3. How did the pull request process help with code quality and collaboration?
   The pull request allowed my work to be reviewed before merging.
   Feedback helped identify mistakes and improve the code.
   It made collaboration more organized and helped keep main stable.
